**公開根拠でつなぐ、エネルギー・産業・デジタルインフラの地図**

GridOS は、韓国・日本・台湾・中国・米国の発電所、送電網、エネルギー
パイプライン、データセンター、ネットワークハブを一つの画面で探索するための
公益公開プロジェクトです。

## GridOS でできること

- 初回アクセス時に、接続地域に合った言語と国別詳細地図から自動的に開始
- 5か国の発電所・送電網・エネルギーパイプライン・データセンター・
  ネットワークハブをレイヤーとして組み合わせて表示
- 国別詳細地図を発電容量、燃料、計画中施設、IX 接続、ネットワーク数で絞り込み
- 公開資料に記載された運営者・所有者・施設間関係と原典を確認
- 地域別の観測電力需要と再生可能エネルギー発電量を比較
- 施設運営者から上場企業・取引所・ティッカーへの公開識別関係を確認
- 韓国語、英語、日本語、中国語（簡体字）で利用

自動選択より、保存されたユーザーの手動選択が常に優先されます。IP 位置情報
サービスは使用せず、新たな位置情報許可も要求しません。ブラウザですでに位置
情報が許可されている場合のみ端末位置を利用し、それ以外はブラウザのタイム
ゾーンと言語を使用します。対応地域を判別できない場合は5か国の全体地図から
開始します。

政策ブリーフの生成と投資推奨は製品範囲に含まれません。企業・ティッカー情報は
公開された識別関係であり、投資助言ではありません。

## 現在のデータ範囲

`v1.0.0` のビルドスナップショットには、5か国で約5.5万件の詳細ポイントと、
送電網・パイプラインなど約3.6万件の線形フィーチャが含まれます。代表施設、
地域需給、運営者・所有者・上場企業の関係には原典を関連付けています。

この地図は、各国の完全な施設台帳ではありません。基準日、公開範囲、位置精度、
集計方法は情報源ごとに異なります。特に「参考供給比率」は、母集団の異なる
観測需要と再生可能エネルギー発電量を比較した値で、電力自給率や系統の余力を
示すものではありません。分析に利用する前に、画面上の原典と方法論を確認して
ください。

## データ公開の原則

GridOS は、公開情報源が直接開示した情報のみを掲載します。

- 非公開の送電網・パイプライン・変電所の位置を推定、復元しない
- 一般化された位置を任意の精密座標へ変換しない
- 単なる近接と、情報源が確認した物理的接続を区別する
- 可能な限り、原典 URL、基準日、取得日時、公開レベルを各レコードに関連付ける
- OpenStreetMap の原データを他の情報源と分離し、公開に必要な属性のみを正規化

主な情報源:

- [OpenStreetMap](https://www.openstreetmap.org/copyright) の公開タグと形状
- [U.S. EIA Form 860](https://www.eia.gov/electricity/data/eia860/)
- [HIFLD 公開インフラデータ](https://hifld-geoplatform.hub.arcgis.com/)
- [PeeringDB 公開 API](https://www.peeringdb.com/apidocs/)
- [中国国家能源局 電力市場報告書](https://www.nea.gov.cn/20250717/54ae0fdb11f04b39a5b670999c04ef81/2025071754ae0fdb11f04b39a5b670999c04ef81_19fe782a11f3aa40209907a80e3e692150.pdf)
- 各国の電力機関、事業者、開示資料、取引所が公開する資料

## 5分以内にローカルで実行

### 必要な環境

- Node.js 20 以降
- pnpm 10 以降

```bash
git clone https://github.com/oswarld/gridos.git
cd gridos
pnpm install
pnpm dev
```

[http://localhost:3000](http://localhost:3000) を開いてください。検証済み
スナップショットがリポジトリに含まれるため、初回のローカル実行に API キーは
不要です。

### データと静的サイトを再ビルド

```bash
pnpm data:build:atlas
pnpm data:build:detail
pnpm data:validate
pnpm build
```

詳細データの生成では公開元データをダウンロードするため、時間がかかる場合が
あります。元データのキャッシュはリポジトリに含まれません。静的エクスポートは
GitHub Pages のプロジェクトパスに対応しています。

## リポジトリ構成

```text
app/                 Next.js ページとロケールのエントリポイント
components/atlas/    地図・フィルター・情報源・関係 UI
data/processed/      検証済み公開アトラスのスナップショット
public/data/detail/  国別詳細地図データ
lib/                 型、翻訳、ドメインロジック
scripts/             収集・変換・検証・静的エクスポート
supabase/            公開読み取り用データスキーマとマイグレーション
```

主な技術スタックは Next.js 15、React 19、TypeScript、MapLibre GL、
Supabase、Tailwind CSS です。

## コントリビューションとセキュリティ

コードとデータへのコントリビューションを歓迎します。

1. 新しい情報源の再配布条件と、許可される位置精度を確認します。
2. 原典 URL、基準日、取得日時、公開レベルを記録します。
3. `pnpm data:validate` と `pnpm build` を実行します。
4. データの誤りや重複は
   [Issues](https://github.com/oswarld/gridos/issues) で報告してください。

秘密鍵、管理者キー、元 API の認証情報をコミットしないでください。脆弱性や
認証情報の漏えいは、公開 Issue ではなく
[セキュリティポリシー](SECURITY.md) に記載された非公開窓口へ報告してください。

## ライセンスと帰属表示

各データセットには、情報源ごとのライセンスと利用条件が適用されます。
OpenStreetMap データには ODbL の帰属表示が必要です。別途ソフトウェア
ライセンスが追加されるまで、ソースコードの公開は再利用許可を意味しません。
